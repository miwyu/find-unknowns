# 実装ノート（実装中）

どれだけ計画しても未知の未知は消えない。構築の途中でしか現れないものがある。ノートファイルは「現地が計画に反対した場所」を記録し、次の計画ラウンドをより良い地図から始めさせる。ノートは*ユーザーの*地図を時間とともに改善する仕組みだ——セッション後に読む人間のために書くこと。走り書きのメモ帳ではない。

## 適用条件

- 計画（または仕様）からの実装が始まる、または進行中で、計画が現実とぶつかる可能性がある。
- ユーザーが「実装ノートを付けて」と言った、または実行中の計画がそう指示している。
- 構築の途中で、計画からの逸脱を強いるエッジケースに当たった——ノートがまだなければ、その時点で始める。

事後の振り返り資料には使わない（それはピッチ／説明資料）。ビルドログでもない——定常的な進捗は書かない。

## 手順

1. 実装の開始時に、`assets/implementation-notes-template.md` を作業リポジトリへ `implementation-notes.md` としてコピーし、**Context** セクションを埋める：タスク、元になった計画の成果物、計画が置いている前提。
2. 構築する。現地が計画と矛盾したら——エッジケース、計画が参照する存在しないファイル、想定と違う挙動の API——**保守的な選択肢を取り、Deviations の下に理由とともに記録して、止まらずに進む**。保守的とは：ユーザーが同意しなかった場合に最も安く巻き戻せる選択のこと。
3. ユーザーにしか答えられない質問は、ブロックせずに **Open questions** に記録する——ただし答えが「巻き戻しの高いもの」を変えるなら、止まって聞く。
4. 逸脱エントリは3点を記録する：計画は何と言っていたか、現地は実際どうだったか、何をしてなぜか。逸脱ひとつにつき1エントリ、起きたその場で書く——最後にまとめて再構成しない。
5. セッションの終わりに、ノートを明示的に手渡す：次の計画ラウンドの入力であり、ピッチ／説明資料の素材でもある。

## 出力契約

- 成果物はユーザーのリポジトリ内の `implementation-notes.md`。テンプレートの必須3見出しに従う：**Context**、**Deviations**、**Open questions**。
- 逸脱は起きた時点で記録し、各エントリは「計画では／現地では／何をしてなぜ」の形。
- セッション終了時の返答では逸脱を2〜4文で要約してファイルを指す——ファイル全文をチャットに貼らない。
- 逸脱がなかった場合も、Deviations の下にその旨を明示する（「なし——計画は現実との接触を生き延びた」）。黙って空にしない。

## 良い例／悪い例

**良い例**（Deviations のエントリ）：

> ### plan.md が参照する src/statsd.js が存在しない
> - **計画では：** レート制限メトリクスを既存の statsd ラッパー `src/statsd.js` 経由で送出する。
> - **現地では：** そのファイルはなく、リポジトリのどこにも statsd がない。最も近い既存物は `src/log.js` の `logger`。
> - **したこと：** `metrics:` プレフィックス付きで `logger.info` からメトリクスを出した——保守的で、巻き戻せて、新規依存なし。本当に statsd が欲しいならそれは新しい決定：Open questions 参照。

**悪い例**（同じ状況）：

> メモ：statsd のファイルがなかったので `node-statsd` をインストールし、localhost:8125 を指すデフォルト設定で src/statsd.js を作成して、計画どおり配線しました。ついでに無関係な lint エラーもいくつか直しておきました。

悪い例は「計画と現実の食い違い」を*欠けていた現実を捏造する*ことで解決している——新規依存と設定の推測は巻き戻しが高く、計画の作者が知るべき「計画の間違い」を黙って決めてしまっている。しかも無関係な修正が混ざり、逸脱が実際何だったのかの記録を汚している。

## 送信前の自己点検

- ノートファイルはリポジトリに存在し、Context が埋まり、Deviations と Open questions があるか——テンプレートからコピーしたもので、即席ではないか？
- すべての逸脱が「計画では／現地では／何をしてなぜ」の形で、起きた時点で記録されているか？
- 逸脱時、最も安く巻き戻せる選択肢を取ったか——そして止まらずに進んだか？
- 計画の間違いが、記録されずに黙って「修正」されたものはないか？ それこそ、このパターンが防ぐために存在する唯一の失敗だ。
- 終了時、次の計画ラウンドの入力としてノートを手渡したか？
