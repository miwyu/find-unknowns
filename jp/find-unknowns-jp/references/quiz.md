# クイズ（実装後）

長いセッション——あるいは他人の変更——の後では、diff は変更の実態を過小に伝える。挙動は diff に映らない既存のコードパスに依存しているからだ。何をなぜ行ったかの文脈と直観をユーザーに渡し、そのうえでクイズを出す。ユーザーに繰り返し伝える価値のある基準：**合格するまでマージしないこと。**

## 適用条件

- 作業（あなた、同僚、または過去セッションによる）が完成し、ユーザーがマージ・出荷・引き継ぎの前に本当に理解する必要がある。
- ユーザーが「この変更についてクイズを出して」「何が起きたか理解できているか確かめて」と言った。
- 変更の挙動が diff の外のコードパスに依存している——まさに、diff だけを読むと偽の自信が生まれる状況。

リダイレクト：読み手が「納得させるべき他者」なら → ピッチ／説明資料。ユーザーが要約だけを求めるなら、レポートを渡してクイズを提案する——その提案が何を防ぐか（誰も理解していないコードへのサインオフ）を添えて。

## 入力

- 変更：diff、PR、またはセッションの出力——**そしてそれが触れる実ソース**。diff がファイルをスタブ化・省略しているならソースが正であり、その食い違い自体がクイズの素材だ。
- ユーザーが下すべき判断（マージ、出荷、引き継ぎ）——それが、問いが保証すべきものを決める。

## 手順

1. diff ではなくソースを読む：変更されたコードが何を呼び、何から呼ばれるかをたどる。
2. 変更の本当のリスク面を地図にする：エラーパス、フォールバック、再起動を生き延びない状態、既存の呼び出し元への静かな挙動変更。
3. レポートを書く：文脈（なぜこの変更が存在するか）、直観（システムの既存概念の言葉でどう動くか——diff 外のパスはここで説明する）、何をしたか、何に注意すべきか。クイズが公平なのは、レポートを読めばユーザーが合格し得る場合だけだ。
4. **トリビアではなく挙動についての質問を4〜7問**書く——鋭いレビュアーが聞く質問。少なくとも1問は答えが diff の外にあるもの、少なくとも1問は失敗パスに関するもの。「ワーカーがジョブの途中で再起動したらリファンドはどうなる？」は「新しいモジュールの名前は？」に勝る。
5. 解答が返ったら：正直に採点し、外した箇所はコードを指し示し、合格するまで変化形を出し直す。

## 初回ターンの契約

成果物ひとつ（チャットメッセージ、求められれば HTML/markdown レポート）を、この順で：

1. **文脈** — この変更が解く問題を、数文で。
2. **直観** — システムの既存挙動と接続した動作原理。
3. **何をしたか** — 具体的な変更を簡潔に。ファイルは貼らずにリンクする。
4. **クイズ** — 挙動に焦点を当てた4〜7問。**答えは伏せる**。
5. 締めの基準：解答は採点され、合格するまでマージ／出荷しないことを推奨する。

## 成果物

レポート＋クイズの成果物。その後（以降のターンで）採点された解答。理解を保証するのはレポートではなく合格だ。

## 停止条件

- 答えを伏せたクイズを届けたら初回ターンを終える——自分の問いに自分で答えない。
- パターンはユーザーが合格したら終わる。それまでは、基準を下げるのではなく変化形を出し直す。

## 良い例／悪い例

**良い例**（非同期リファンド変更へのクイズ2問）：

> 3. リファンドジョブがワーカーに拾われ、決済プロバイダの呼び出しは成功したが、DB 書き込みの前にプロセスがクラッシュした。顧客がリトライする。**二重にリファンドされるか？ 理由も含めて説明せよ。**
> 4. `recent-change.diff` では `queue.js` がスタブになっている。実ソースでは、**バリデーションに失敗したジョブはどうなり——誰がそれを知るか？**（ヒント：catch ブロックがジョブをどうしているか見よ。）

**悪い例**（同じ変更）：

> 3. 追加された新しいファイルの名前は？
> 4. ○か×か：リファンドエンドポイントは HTTP 202 を返すようになった。
> 5. キューは何回リトライを試みるか？

悪い例はトリビアだ——diff を流し読みすれば答えられ、理解せずに暗記でき、どの問いも本物の地雷（バリデーション失敗ジョブが静かに落ちる）を捕まえない。ユーザーは満点を取ってなお、説明できないサイレント・デッドレターのバグをマージし得る。

## 送信前の自己点検

- 変更が触れる実ソースを読んだか——スタブ化された diff の裏を取ったか？
- 質問は4〜7問で、すべて**挙動**についてか（レビュアーの障害ポストモーテムの質問と置き換え可能か）？
- 少なくとも1問は diff の外の知識を要求し、少なくとも1問は失敗パスを扱っているか？
- 初回ターンで答えは伏せられているか？
- レポートを読めば、ユーザーは合格し得るか？
- 「合格するまでマージしない」の基準を明言したか？
