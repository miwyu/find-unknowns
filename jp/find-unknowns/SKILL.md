# Find Unknowns（未知の発見）

依頼と現実の制約の隔たりを解消し、本質でない選択は開いたままにする。枠組みを説明するだけで終えず、適切なパターンを実行する。

## 意図・範囲・ルーティング

明示的な意図（名指しされたパターンや成果物、実行段階を含む）を以下の既定値より常に優先する。実装途中のブレストやマージ後の盲点調査も尊重する。要約だけなら要約を届け、クイズは押し付けず提案にとどめる。明示的な発見依頼がなければ、定型作業や仕様確定済みの作業に発見プロセスを足さず直接対応する。確定済みの決定と既存の承認を守り、新しい証拠で覆せるのは影響する決定だけとする。調査や下書きから実装・公開・送信の許可を推測しない。

パターン指定がない場合は、最初に当てはまる既定ルートを使う：

- 完了作業を説明したい → **ピッチ／説明資料**。理解を確かめたい → **クイズ**。
- このスキルの実行中に実装している、または逸脱記録を求められた → **実装ノート**。合意済み計画だけでは発動しない。
- それ以外で実装前または影響する方針を再検討中なら、現在のボトルネックで選ぶ：
  1. 結果を表す実例を指定 → **リファレンス探し**。
  2. 言語化できない好みや未選択の範囲に案が必要 → **ブレインストーム＆プロトタイプ**。
  3. 不慣れな領域、または調査・計測が必要な事実 → **ブラインドスポットパス**。先に証拠を調べる。処理能力や実現可能性は、ユーザーの推測でなく許可範囲内の小さな検証か代表条件の計測で確かめる。
  4. 意図は固まり、ユーザーだけが決める重要な選択が残る → **インタビュー**。
  5. 要件が固まり、レビュー可能な計画が必要 → **実装計画**。

文脈から出発点を推定し、次の有用な行動が変わる不足情報に限って、焦点を絞った確認を既定で一つまで行う。選んだパターンと出発点を短く伝える。一度に一つのパターンを実行し、回答・証拠・参照の引き継ぎでボトルネックが変われば見直す。参照先へのリダイレクトは既定値であり、明示依頼を覆す許可ではない。

## ステップ3 — 参照ファイルを読む

選んだ参照だけを読む。`references/` と `assets/` はこの `SKILL.md` のあるディレクトリからの相対パスであり、作業リポジトリからではない。読めない資料があれば制約を述べ、読んだと主張しない。

| パターン | ファイル |
|---|---|
| ブラインドスポットパス | `references/blind-spot-pass.md` |
| ブレインストーム＆プロトタイプ | `references/brainstorm-prototype.md` |
| インタビュー | `references/interview.md` |
| リファレンス探し | `references/reference-hunting.md` |
| 実装計画 | `references/implementation-plan.md` |
| 実装ノート | `references/implementation-notes.md` |
| ピッチ／説明資料 | `references/pitch-explainer.md` |
| クイズ | `references/quiz.md` |

各参照は8セクション（適用条件、入力、手順、初回ターンの契約、成果物、停止条件、良い例・悪い例、送信前の自己点検）を持つ。`assets/implementation-notes-template.md` は開始用素材であり、依頼された成果物を制限しない。

## ステップ4 — 依頼の範囲内で実行する

以下を手順、契約、例、自己点検のすべてに適用する：

- **優先順位：** 利用環境の指示と権限の範囲で、ユーザー指定の範囲・形式・件数・継続・中止をスキル既定値より優先する。それ以外はパターン契約、共通既定値の順とする。必要な入力を待つ依存作業は止め、独立した許可済み作業は続ける。得た承認を求め直さない。
- **確認質問：** 既定では1返信につき必須の確認は最大一つ。任意の文脈提供は必須回答ではなく、クイズの設問は成果物である。複数の問いを一文に詰めて回避しない。
- **件数：** 発見・決定は通常、順位付き3〜5個（十分なら少なくてよい）。既定はブレストがモック3〜5個または範囲案5〜10個、リファレンスが性質3〜7個、クイズが4〜7問。これらは共通既定件数に優先し、捏造して下限を埋めない。網羅性や別件数の明示指定を守る。補足説明と計画手順は追加のユーザー判断に数えない。
- **証拠：** 観測事実、解釈、未検証の仮定、ユーザーの選択を分け、実在するファイルや情報源を示す。ソース確認は測定済み・配備済み挙動の証明ではない。アクセス不足なら利用できる証拠を使い、未検証事項と具体的な次の確認を示す。アクセスや結果を捏造しない。
- **利用能力：** 特定のツール名を必須にせず、利用できる機能で進める。質問UIがなければ通常文で聞く。書込み・表示ができなければ、未保存・未表示と明示した使える文章やスケッチを渡し、作成・確認できない成果物を主張しない。
- **自律性：** 要件と承認を満たす選択肢では巻き戻しやすい変更を選び、逸脱を記録して続ける。巻き戻せることだけを理由にアクセス制御や外部契約を弱めない。重要な未決のユーザー判断か不足する許可だけを確認し、依存やスキーマだけでは止まったり再承認を求めたりしない。
- **出力：** 行動できる発見、質問、候補群、計画、成果物、完了作業を届ける。頼まれていないテンプレートや網羅チェックリストを足さず、言語と長さを読み手に合わせる。

## ステップ5 — 自己点検

選んだ参照の自己点検を、ステップ4の優先順位で適用する。直せる不備は直す。証拠・ツール不足で点検できないものは合格を捏造せず、制約と残る確認を示す。中止や方向変更の依頼を尊重する。
