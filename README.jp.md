# find-unknowns

自分のタスクについて「自分が何を分かっていないか」を、実装の前・最中・後に発見するための Claude Code スキルです。

## このスキルがやること

エージェンティックコーディングの品質を決めるボトルネックは「未知（unknowns）」——つまり、依頼した内容と、実際の作業が要求するものとのギャップです。このスキルを使うと、Claude はファシリテーターとして、いまどの種類の未知がボトルネックかを診断し、適切な発見パターンを自分から実行します。

| あなたの状況                                                   | Claude が実行するパターン                                                                           |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| ドメインやコードベースのその部分に不慣れ                       | **ブラインドスポットパス** — 先に現場を調査し、「聞くべきだったのに知らなかったこと」を教えてくれる |
| 「見れば分かるんだけど言葉にできない」（デザイン・UX・トーン） | **ブレインストーム＆プロトタイプ** — 方向性の異なる安価なモックを複数作り、反応してもらう           |
| 仕様はあるが、聞かれれば答えられる空白がある                   | **インタビュー** — 一度にひとつずつ、アーキテクチャを左右する質問から                               |
| 言葉にできないが、参考になる実例がある                         | **リファレンス** — 実例を読み込み、転用できる本質を抽出する                                         |
| 実装を始める準備ができた                                       | **実装計画** — 決めるべきことを先頭に、機械的な作業は最後に                                         |
| 実装の真っ最中                                                 | **実装ノート** — 計画からの逸脱をすべて `implementation-notes.md` に記録し続ける                    |
| 完成後、関係者の承認が必要                                     | **ピッチ／説明資料** — 判断の経緯をレビュアー向けにひとつの資料へ                                   |
| 完成後、マージする直前                                         | **クイズ** — 変更内容の理解度クイズ。合格してからサインオフ                                         |

このスキルは意図的に「軽く」設計されています。1ターンにつき必須の質問はひとつだけ、提示する論点は最大3〜5個（残りは保留して提案のみ）、頼まれない限り穴埋めテンプレートは出しません。そして必ず、すぐ行動に移せる成果物——多くの場合、元の依頼文を研ぎ直したプロンプト——で締めくくります。

## 使いどころ

- 大きい・曖昧・仕様が固まっていないタスク（「アプリに通知機能つけて」など）
- 触ったことのないドメイン・ライブラリ・コードベースの領域での作業
- 選択肢を見て初めて好みが分かる、センスが問われる作業
- 自分で一行ずつ書いたわけではない大きな変更をマージする前

## 使わないほうがよい場面

- タスクがすでに完全に仕様化されている——そのまま実装すればよい
- 合意済みの仕様があり、決定を蒸し返してほしくない
- 定型作業：原因の明確なエラーのデバッグ、リネーム、小さく範囲の明確な修正

## インストール

**英語版** — パッケージ済みスキルをスキルディレクトリに展開します：

```bash
# グローバルに
unzip find-unknowns.skill -d ~/.claude/skills/

# または特定のプロジェクトだけに
unzip find-unknowns.skill -d <your-project>/.claude/skills/
```

**日本語版** — このリポジトリのフォルダをコピーします：

```bash
cp -r jp/find-unknowns-jp ~/.claude/skills/
```

名前が異なる（`find-unknowns` / `find-unknowns-jp`）ため、両方を同時にインストールしても問題ありません。

## 使い方

明示的に呼び出すのが確実です：

> 「始める前に**ブラインドスポットパス**をやって。認証まわりのコードは触ったことがないんだ」
> 「作り始める前に、この機能について**インタビューして**」
> 「マージする前に、この変更について**クイズを出して**」

**自動発動についての注意：** このスキルの説明文（トリガー条件）は意図的に控えめにチューニングされています。明らかに仕様が曖昧な依頼では自動的に発動することもありますが、「実装する準備ができている人の邪魔は絶対にしない」ことを最優先にしています——発動率よりも誤発動ゼロを選びました。特定のプロジェクトで積極的に発動させたい場合は、そのプロジェクトの `CLAUDE.md` に一行追加してください。例：_「依頼が曖昧なときは find-unknowns スキルを使うこと」_

## 検証について

このスキルは、5つの採点付きシナリオ（ブラインドスポットパス、デザイン方向性、曖昧な機能依頼、実装中の計画逸脱、マージ前クイズ）からなるベンチマークスイートで、スキルあり／なしを比較しながら開発されました。評価の定義とフィクスチャは [`evals/`](evals/) にあり、実行・拡張できます。
