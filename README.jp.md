# find-unknowns

自分のタスクについて「自分が何を分かっていないか」を、実装の前、最中、後に見つけるためのAIエージェント向けスキルです。Agent Skills形式を使い、まずCodexとClaude Codeを対応対象にしています。

## このスキルがやること

依頼したとおりに作ってもらったのに、できあがったものは望んだものと違っていた。そういう経験は、指示の書き方が下手だったせいとは限りません。依頼した内容と、実際の作業が要求するものとのあいだには、依頼者自身がまだ気づいていないギャップ（**未知**、unknowns）があります。エージェンティックコーディングの品質は、この未知に上限を決められます。

自分で気づけないものを、自分で埋めることはできません。そこでこのスキルは、AIエージェントをファシリテーターにします。いまボトルネックになっている未知がどの種類かを診断し、それに合った発見パターンを エージェントのほうから実行します。

| あなたの状況                                                 | エージェントが実行するパターン                                                                          |
| ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| ドメインやコードベースのその部分に不慣れ                     | **ブラインドスポットパス**：先に現場を調査し、「聞くべきだったのに知らなかったこと」を教えてくれる |
| 「見れば分かるんだけど言葉にできない」、またはスコープ未確定 | **ブレインストーム＆プロトタイプ**：安価なモック3〜5個、または安い順の1行案5〜10個に反応してもらう |
| 仕様はあるが、聞かれれば答えられる空白がある                 | **インタビュー**：一度にひとつずつ、アーキテクチャを左右する質問から                               |
| 言葉にできないが、参考になる実例がある                       | **リファレンス**：実例を読み込み、転用できる本質を抽出する                                         |
| 実装を始める準備ができた                                     | **実装計画**：決めるべきことを先頭に、機械的な作業は最後に                                         |
| 実装の真っ最中                                               | **実装ノート**：計画からの逸脱をすべて `implementation-notes.md` に記録し続ける                    |
| 完成後、関係者の承認が必要                                   | **ピッチ／説明資料**：判断の経緯をレビュアー向けにひとつの資料へ                                   |
| 完成後、マージする直前                                       | **クイズ**：変更内容の理解度クイズ。合格してからサインオフ                                         |

表の上から五つは実装前、六つめは実装中、残りの二つは実装後に当たります。同じ「分かっていない」でも、段階ごとに正体が違う、ということです。

発見のための対話は軽く保つことを目指しています。重要な決定を優先し、確認の質問は一つずつ行い、頼まれていない穴埋めテンプレートは渡しません。依頼文から読み取った出発点を伝え、行動できる次の一手につなげます。共通規則は確認質問と依頼された成果物を区別し、明示された範囲と件数を尊重する形へ改訂しました。行動検証は残っています。[第2段階の検証記録](docs/stage-2-validation.md)を参照してください。

## スキルの構成

八つのパターンを一つのスキルに詰めると、エージェントが毎回読む量が膨らみそうに思えます。実際に読むのは、ルーターと、選んだパターンのリファレンス一つだけです。

```text
find-unknowns/
├── SKILL.md        # 6ステップの指示ルーター：非適用判定 → 段階（ライフサイクル）判定 →
│                   # パターン選択（最初に一致した規則が勝つ） → 参照読込 →
│                   # 実行（数えられるガードレール） → 二値の自己チェック
├── references/     # 1パターン1ファイル。エージェントは選んだ1ファイルだけを読む
│                   # （各ファイル：適用条件、入力、手順、初回契約、成果物、
│                   #   停止条件、良い例／悪い例の対照、二値の自己チェック）
└── assets/
    └── implementation-notes-template.md   # 実装ノートパターンが、あなたのリポジトリへコピーする
```

パターンごとの説明は、必要なときに読み込みます。件数制限は挙動を評価しやすくするためにこのリポジトリで加えた規約であり、モデル間で同じ動作を保証するものではありません。

## 使いどころ

- 大きい、曖昧、仕様が固まっていないタスク（「アプリに通知機能つけて」など）
- 触ったことのないドメイン、ライブラリ、コードベースの領域での作業
- 選択肢を見て初めて好みが分かる、センスが問われる作業
- 自分で一行ずつ書いたわけではない大きな変更をマージする前

どれも、自分が何を知らないかを自分では言えない状態です。

## 使わないほうがよい場面

- タスクがすでに完全に仕様化されている。そのまま実装すればよい
- 合意済みの仕様があり、決定を蒸し返してほしくない
- 定型作業。原因の明確なエラーのデバッグ、リネーム、小さく範囲の明確な修正

こちらは、分かっていないことがもう残っていないか、残っていても今は決めたくない状態です。割り込む価値がありません。

## 導入と使い方

**言語を一つ選びます。** 英語版は `find-unknowns/`、日本語版は `jp/find-unknowns/` をコピーしてください。どちらも名前は `find-unknowns` なので、同じ環境には原則どちらか一方を導入します。`SKILL.md` だけでなく、`references/` と `assets/` を含むディレクトリ全体が必要です。開発に使ったskill-creatorプラグインは、利用時には不要です。

| 環境 | プロジェクト用の配置先 | 個人用の配置先 | 明示的な呼び出し |
| --- | --- | --- | --- |
| Codex CLI / IDE | `.agents/skills/find-unknowns/` | `~/.agents/skills/find-unknowns/` | `$find-unknowns` |
| Claude Code | `.claude/skills/find-unknowns/` | `~/.claude/skills/find-unknowns/` | `/find-unknowns` |

配置先と呼び出し方は、2026-09-06に確認した[Codex公式文書](https://learn.chatgpt.com/docs/build-skills)と[Claude Code公式文書](https://code.claude.com/docs/en/skills)に基づきます。プロジェクト用のパスは、スキルを使いたいプロジェクトを基準にします。この開発リポジトリに置くとは限りません。

Codexへ個人用の日本語版を新規導入する例です。このリポジトリのルートから実行します。

```sh
mkdir -p ~/.agents/skills
# 配置先がまだ存在しない場合だけコピーします。
test ! -e ~/.agents/skills/find-unknowns && cp -R jp/find-unknowns ~/.agents/skills/find-unknowns
```

Claude Codeでは配置先を `~/.claude/skills` に、英語版ではコピー元を `find-unknowns` に変えます。プロジェクト用の場合は表の該当パスを使います。既存の導入がないか確認し、ディレクトリの入れ子や版の混在を避けてください。

導入後は、スキルを名指しして具体的に依頼します。

```text
$find-unknowns 作業を始める前に、認証コードのブラインドスポットパスをして。
```

Claude Codeでは `$find-unknowns` を `/find-unknowns` に置き換えます。「作り始める前にこの機能についてインタビューして」「マージ前に変更についてクイズを出して」も依頼例です。通常の文章でパターン名を伝えるだけでは、スキルが実際に読み込まれたとは限りません。

スキル選択UI（Codexでは `/skills` または `$`、Claude Codeでは `/`）に表示されることを確認し、呼び出し後に本体と適切な参照ファイルが読み込まれるかを確認します。表示されなければ配置を確認し、利用環境を再起動してください。この確認は読み込みの確認であり、行動評価ではありません。

更新時はローカルの変更を退避してから、導入済みディレクトリを選んだ言語の完全なツリーで置き換えます。削除時は、その導入済みディレクトリだけを取り除きます。プロジェクト用と個人用の重複を避け、できるだけ一つの導入で管理してください。

自動選択の説明文は、仕様が確定した作業や定型作業に割り込まないよう慎重にしています。過去のClaude単独セッションでは自動選択の再現率が低く、誤発動ゼロも設計目標であって保証ではありません。明示的な呼び出しを推奨します。特定プロジェクトで選択を促したい場合は、Codexでは `AGENTS.md`、Claude Codeでは `CLAUDE.md` に「依頼が曖昧なときは find-unknowns スキルを使うこと」と追記します。

## 対応状況と検証

| 環境 | 現在の確認範囲 | 未確認の範囲 |
| --- | --- | --- |
| Codex CLI / IDE | 英日ともローカルの形式検証に合格。導入手順は公式文書に準拠 | クリーンな環境での導入、明示・自動選択、行動評価 |
| Claude Code | 過去のスキル版で行動評価の実績あり | 現行版の導入と全シナリオの動作確認 |
| その他のAgent Skills対応環境 | 共通形式を移植性の基準として採用 | 各環境での選択、ツールアクセス、動作確認 |

スキル機構がない環境では、指示と必要な参照ファイルを手動で渡す方法もありますが、ネイティブ対応と同等ではありません。ファイル・Webへのアクセスや成果物の表示能力は環境によって異なり、改訂した本体に代替動作を記述していますが、その挙動は未検証です。

追跡済みの評価は、**英日21シナリオ・87アサーション**と、**英日20件の選択クエリ**（発動対象10件・非対象10件）です。定義とフィクスチャは [evals/](evals/) にあります。

従来紹介していた **41/41** は、iteration 7（2026-07-11）の8シナリオ、各条件1回の実行で、当時の改訂版をClaude Fable 5とClaude Sonnet 5で評価した結果です。現行版やCodexの結果ではありません。その後は部分的な検証であり、iteration 9（2026-09-06）は対象8実行すべてが認証失敗で、行動評価の結果は得られていません。

クリーンなcloneから使えるPython標準ライブラリの実行基盤、根拠付き採点テンプレート、構造検証CIを追加しました。[評価手順](evals/README.jp.md)と[第3段階の検証記録](docs/stage-3-validation.md)を参照してください。モデル実行はClaudeの認証とCodex実行ファイルの欠落により停止しており、新たな行動評価の点数はありません。過去の生ログとパッチ済みツールは引き続きGit管理外です。[過去の評価手順](docs/legacy-claude-evaluation.md)に経緯を残しています。

## 出典と開発

着想元は、AnthropicのThariq Shihiparによる [A field guide to Claude Fable 5: Finding your unknowns](https://claude.com/blog/a-field-guide-to-claude-fable-finding-your-unknowns)（2026年7月6日公開）です。このリポジトリは、その発見パターンをもとに独自のルーティング・出力契約・評価を実装したものです。

[設計方針と出典](docs/design.jp.md)では、記事から継承した原則と独自規約を分け、4段階の移行状況を記録しています。開発時の共通指示は [AGENTS.md](AGENTS.md) にあり、[CLAUDE.md](CLAUDE.md) からも読み込みます。
