英語descriptionを627→169文字（73.0%削減）、日本語を213→78文字（63.4%削減）に変更した。文字数はPythonの`len`であり、トークン数ではない。本文・参照・評価定義は変更していない。試した候補のうち、両言語で現行版の観測性能を維持した最短の組を採用した。

## 方法と範囲

独立した実行者による評価と反復改善の手順に従い、最初にdescriptionと本文の整合性を確認した。用途と本文の8パターンに矛盾はなかった。各評価は`collaboration.spawn_agent`の新規エージェント、`fork_turns=none`、指定モデル`gpt-5.6-luna`で実行した。正確なホスト・解決済みモデルのバージョンは機能から返されなかった。

既存の20選択クエリを英日で40問として使い、順番を固定シャッフルした。未使用の追加12問は初回の結果を読む前に固定した。descriptionだけを渡す選択シミュレーションであり、各バッチ内で独立判断を指示した。1問ごとの独立セッションではない。評価者には正解ラベル・リポジトリ指示・本文を渡していない。

チェック項目は事前固定した「各問の選択正解との一致 [critical]」「全IDの重複なき回答」「不明瞭点・裁量・再試行の申告」。選択精度は各問の一致率で、表の成功はcritical全件一致時のみ○とする。基準版にも誤選択があるため、採否には同一問題での退行有無も用いた。自己申告と判定理由は別々に確認した。

モデル実行はすべて一時ディレクトリ内の入力・複製スキルで行い、pristine fixturesは使用・変更していない。ツールはセッションから継承されるため、隔離は入力と指示の範囲であり、セキュリティ境界ではない。

## 停止理由と限界

停止はリソース打ち切りであり、skillの厳密な数値収束を達成したとはしない。新規description解釈問題が増えず、最終2実行で選択結果は安定したが、usageの`tool_uses`と`duration_ms`が取得できず±10%／±15%の閾値を検証できない。さらに短い日本語候補は性能低下を起こした。これ以上の圧縮より観測した区別を保持する方を選んだ。絶対最短や、未知の依頼すべてでの性能維持は未証明。

これはdescription選択のシミュレーションと2ケースの明示パスによるbehavior probeであり、ネイティブなスキル発見、21ケース全体、他モデル、Claude Codeでの動作を検証したものではない。既存CLI runnerによるbenchmarkや`score-triggers`の観測結果に混ぜない。親に生のツールtraceが返されないため、実ホスト発動や全副作用のtrace監査も主張しない。

構造・ツール検証は別途、`python3 tools/evaluate.py validate`（21 cases / 87 assertions / 両言語）と`python3 -m unittest discover -s tests -v`（22 tests）を通過した。
