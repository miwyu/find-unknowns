## 短縮を戻した理由

当初は入口と全参照を圧縮し、全体で英語約51%、日本語約58%削減した。しかし次の失敗があり、総合点だけで採用しなかった。

| 試行                | 観測                                           | 対応                                      |
| ------------------- | ---------------------------------------------- | ----------------------------------------- |
| 入口＋全参照        | 欠けた基盤を理由に独立した実装まで停止         | notesの継続条件を明確化して再実行         |
| notesの修正         | 実装は進んだが永続ノートを保存しない           | notesを復元し、明示呼び出し時の分岐を補足 |
| 分岐補足＋notes復元 | 実装停止が残る                                 | 入口も元版へ戻す                          |
| 7参照短縮、再実行   | 一案しか作らない試作、呼び出し側awaitの誤読    | ブレストと盲点調査を元版へ戻す            |
| 5参照短縮の追加実行 | 参照アダプターのJSON POST bodyを抽出から落とす | リファレンス探しも元版へ戻す              |

同一の入口・notesを使った試行でも実装停止と実装継続の両方が観測されており、すべての失敗を短縮の因果効果とは言えない。追加smoke実行では、元版のままのブレスト／盲点調査に分岐して複数質問をする例も出た。こうした揺れは不採用案とともに記録した。
