# 評価手順

[English](README.md)

リポジトリ直下でPython 3.10以上を使います。実行基盤とテストは標準ライブラリのみで動き、構造検証に非公開プラグイン、変更済みskill-creator、モデル認証は不要です。モデル実行には導入・認証済みのClaude CodeまたはCodex CLIと、明示的なモデルIDが必要です。

```sh
python3 tools/evaluate.py validate
python3 -m unittest discover -s tests -v
python3 tools/evaluate.py run --host claude --model MODEL_ID --output find-unknowns-workspace/preview --language en ja --variant with_skill without_skill --dry-run
```

出力先は毎回新しいディレクトリにします。dry-runはCLIバージョンと初回入力の生成を確認します。モデルを呼ばず、後続ターンの応答も捏造しません。CIはUbuntu、Python 3.10/3.12で構造検証と実行基盤のテストを行います。モデルは実行しません。

## 行動評価

```sh
python3 tools/evaluate.py run --host claude --model MODEL_ID --output find-unknowns-workspace/claude-run --language en ja --variant with_skill without_skill --repeats 3
python3 tools/evaluate.py run --host codex --model MODEL_ID --output find-unknowns-workspace/codex-run --language en ja --variant with_skill without_skill --repeats 3
```

`MODEL_ID`を利用可能なモデルIDに置き換えます。一部だけ実行する場合は `--cases 9 10 11 12`、各ターンの制限時間は `--timeout 180`、実行ファイルの指定は `--binary /absolute/path/to/cli` を使います。導入やログインは自動で行いません。終了コード2は検証・起動・実行・採点のエラーです。`blocked.json`、`preflight.json`、各ターンの結果を確認してください。認証・起動エラーでは残りを停止します。完了したモデル実行がなければ行動評価の点数は出ません。

各実行はリポジトリ外の新しい一時ディレクトリへフィクスチャと初期ファイルをコピーします。書き込み対象もコピーで、毎回元のハッシュを照合します。開発用AGENTS.md、期待する回答、採点基準は評価対象へ渡しません。スキルありではコピーしたSKILL.mdを明示し、なしではコピーも指示も省きます。これはファイルパスを明示した後の動作評価であり、標準の導入や自動選択の検証ではありません。

複数ターンでは、実際に得られた会話を新しいCLIプロセスへ渡し、作業ファイルを維持します。前の応答が完了するまで後続の依頼を渡しません。会話を与えた際の継続性を評価し、ホスト本来のセッション再開や内部状態の保持は評価しません。

## 利用できる機能と比較上の制約

| 環境 | 読み取り | 書き込み | 設定 |
| --- | --- | --- | --- |
| Claude Code | Read、Glob、Grep | 左記とWrite、Edit | safe mode、セッション保存なし、権限確認なし |
| Codex | read-only sandbox | workspace-write sandbox | approval never、web検索無効、ephemeral |

通信とレンダリングは利用不可と伝えます。依存の導入や権限回避は行いません。この基盤自体はセキュリティ境界ではなく、ホストのツールや共通指示には差が残ります。Codexはローカル設定とユーザースキルを引き継ぎます。比較には、このスキルを別途導入していない専用のクリーンな環境を使い、ログで混入を確認してください。同じホスト・モデル・言語・機能・設定・対象ケース・反復数で比較します。ホスト間の点差をスキルの効果と解釈しないでください。環境固有の設定変更は別途記録します。認証情報や全グローバル設定は保存しません。

ケース5はStripeの実際の調査が必要なため、dry-runでも `unsupported_capability` と記録して採点から除外します。ケース12は参照ソースを入力に含め、14は証拠を取得できない場合を扱います。通信を伴う調査と標準のスキル選択は第4段階の確認事項です。

Codexの引数とJSONL形式は、2026-09-06に確認した[公式コマンド文書](https://learn.chatgpt.com/docs/developer-commands?surface=cli)と[非対話実行の文書](https://learn.chatgpt.com/docs/non-interactive-mode)に基づきます。Claudeの引数はローカル2.1.234の `--help` で確認しました。両環境の実動作は未検証です。[第3段階の検証記録](../docs/stage-3-validation.md)を参照してください。

## 出力と採点

出力にはコミット・未コミット変更の有無、評価定義と実行スクリプトのハッシュ、本体とフィクスチャのハッシュ、本体・評価定義のコピー、CLIバージョン、指定モデル、呼び出し方式、対象ケース、反復数を保存します。各実行にはコマンド、入力、JSONLと標準エラー、判定した状態、ホストが返した使用量、会話、初期ファイル、成果物と変更一覧があります。実際のモデル名はホストが報告した場合に保存します。明示的に公開対象を選ばない限り、出力はGit管理外です。

応答が完了すると `runs/<condition>/grading.json` ができます。全ターンの回答、ツール記録、成果物を確認し、`grader` に採点者またはモデル・版・採点方法、各項目の `passed` に真偽値、`evidence` に具体的な根拠を記入します。回答の引用箇所や成果物のパス・行番号を示し、単語の一致や「書いた」という自己申告だけでは判定しません。採点は評価対象のプロセス外で行います。nullを含む採点は未完了のままで、部分的な点数は出しません。

```sh
python3 tools/evaluate.py aggregate find-unknowns-workspace/claude-run
```

`benchmark.json` と `benchmark.md` に、ホスト・モデル・言語・スキル有無別の結果を出します。合格率の分母は、実行と全項目の採点が完了したものだけです。エラー、タイムアウト、プロトコル異常、機能不足、dry-run、未採点は区別します。率と一緒に対象数・状態別件数も報告し、一部の採点を全件の結果として扱わないでください。根拠なし、真偽値以外の完了判定、採点文の不一致は集計エラーになります。意味に基づく自動採点や統計的有意差検定は行いません。

再現用に共有する際は、実行情報、定義のコピー、入力、生ログ、回答、成果物、採点を揃え、生成内容を確認してから公開します。過去のローカル実行とは分けて管理します。

## ケース一覧

21ケース・87アサーションで、全ケースに英日入力があります。0〜8は既存ケースで、第2段階に採点基準を揃えました。9〜12はローカルにあった追加案です。正確な定義はJSONを参照してください。

| ID | 対象 |
| --- | --- |
| 0〜8 | 8パターンと基本的な作業範囲の境界 |
| 9〜12 | 実装中の明示ブレスト、マージ後の明示盲点調査、実証的な未知、参照から7項目の抽出 |
| 13〜14 | 既存ノートと指定パスの保持、取得できない参照 |
| 15〜16 | 決定済み事項を踏まえたインタビュー継続、クイズ中止 |
| 17〜20 | 計画から承認済み実装への継続、文体比較、要約限定、未保存ノート |

各ケースに英日入力、フィクスチャ、機能設定、採点基準を持たせ、必要に応じて初期ファイルと後続ターンを指定します。初期ファイルはコピーだけに適用します。フィクスチャの意図的な欠陥は修正しません。構造検証は、このリポジトリの単一行frontmatter、参照パス、英日ファイル構成、参照の構造、評価入力を確認します。翻訳の意味の一致を証明するものではありません。

## 標準の自動選択の観測

選択クエリ20件にも英日版があり、各言語で発動対象10件・非対象10件です。行動評価の点数には含めません。

```sh
python3 tools/evaluate.py trigger-template --host codex --model MODEL_ID --language ja --output find-unknowns-workspace/triggers-ja.json
python3 tools/evaluate.py score-triggers find-unknowns-workspace/triggers-ja.json
```

テンプレートには正解ラベルがあるため、観測者だけが使用します。一方の言語だけ導入したクリーンな環境で、クエリごとに新規セッションを開き、`query` のみを送ります。スキルの明示呼び出しや正解、採点指示は渡しません。実際の呼び出し・読み込み記録から `selected` を判定し、自己申告や回答の雰囲気で判定しません。非発動は、呼び出しがないことを確認できる完全なログを根拠にします。ホストのエラーや不完全な記録はnullのままにします。ホスト版、観測者、導入方法も記入してください。保存された質問・正解ラベル・本体ハッシュを維持し、ホスト・モデル・言語・反復・本体版ごとに新規ファイルを作ります。

集計は真陽性・偽陽性・真陰性・偽陰性、適合率、再現率、未観測数を出します。分母0はnullです。手動で記録した観測の集計であり、自動選択を実行・認証する機能ではありません。標準の導入と実際のログ収集は第4段階で行います。
